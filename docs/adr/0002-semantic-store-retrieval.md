# 语义层存储与检索：独立 PG 实例 + YAML 作者入口 + RRF 混合检索

> ⚠️ **已被修正**：存储载体由「独立 PG 实例」改为「SQLite 单文件」（v1 唯一实现，PG 作升级路径）——见 [ADR-0005](./0005-semantic-store-sqlite.md)（票据 13）。本 ADR 的检索方案（五条原语 + RRF + OpenAI embedding + 不引入图数据库）与作者入口/同步管线决策原样有效。

语义层运行时存储 = 同机房**独立 PG 实例**（与生产集群隔离，同步管线零生产凭证），作者入口 = **按服务拆分的 YAML 语义模型文件**（+ 全局指标/概念文件），自研 Go 同步管线编译、校验、增量同步（幂等 upsert + 墓碑软删除 + dry-run diff）；运行时**只查 PG，不查 YAML**。检索 = 五条数据层原语（FQN 精确 / 双入口关键词 / 类型化边遍历 / 指标公式 / 枚举值），`search_entities` 走 **RRF（Reciprocal Rank Fusion）混合**——pg_trgm 关键词主通道优先 + pgvector 向量兜底，不设固定比例；v1 引入向量，embedding 用外部 OpenAI text-embedding-3（接受元数据出机房）。不引入图数据库（边表 + WITH RECURSIVE）。来源：票据 07（issue #8），2026-08-11 拍板。

## Considered Options

- **现有集群内独立 database**（与业务库同集群）：零新增基础设施、自动吃集群备份/监控/复制；但同步管线必须持有**生产集群写权限**——违背本项目第一原则「不暴露生产库连接」，把最大的口子开给自动解析 YAML 并写入的进程。→ 未选。
- **独立 PG 实例（选定）**：同机房小规格 VM/容器，同步管线只持语义实例自己的凭证，全程不碰生产集群；业务集群故障转移不影响语义层；MB 级数据下备份 = pg_dump 脚本，运维成本可忽略。网关两个端点：业务从库 + 语义实例。部署细节（规格/TLS/端口）留票据 11。
- **运行时直接查 YAML / 内存加载**：MB 级数据技术上可行；但检索原语是 SQL 形态（无索引则关键词/多跳检索质量降级）、权限/审计与语义层割裂、增量更新需重启或自做热加载。→ 未选，文件只作作者入口。
- **纯关键词检索（06 原方向）**：精确标识符召回强、零基建；但自然语言 ↔ 概念名的语义匹配弱（用户说"支付失败率"，指标叫 `failure_rate`）。→ 被修正：v1 引入向量，关键词仍主通道。
- **固定比例混合（0.6 关键词 + 0.4 向量）**：两种检索打分尺度不可比、调参脆弱。→ 未选，改用 RRF 排名融合，关键词命中排向量命中之前（06 实证：精确标识符召回词法强于向量）。
- **embedding 自托管 Ollama vs 外部 API**：自托管数据不出机房但新增服务；外部 API 零运维但元数据（表名/描述/枚举）出机房。→ 外部 OpenAI text-embedding-3（拍板人选择，合规取舍记录在案）；embedding 在同步管线内生成，增量只嵌入变更实体。

## Consequences

- 同步管线与网关的凭证边界：语义实例独立凭证，**零生产凭证**——「不暴露生产库连接」原则延伸到语义层自身。
- 五条检索原语是票据 02 工具面（每条映射一个只读 MCP 工具 + 轻量 Agent Skill）与 03（FQN 权限挂载点）的输入。
- 指标公式机器可读（原语 4）是票据 10 dry-run 与 SQL 规划的直接输入。
- 墓碑语义（软删除、检索默认过滤）与按服务落盘是票据 08 知识采集/保鲜的输入。
- 元数据经 OpenAI API 出机房——如合规要求收紧，回退路径是自托管（模型换 bge-m3 等，向量列无需迁移）。
- 语义实例的部署细节（机器规格、TLS、端口）由票据 11 钉死，本 ADR 不决定。
