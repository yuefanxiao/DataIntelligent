# 语义层运行时存储：SQLite 轻量版（修正 ADR-0002）

v1 语义层运行时存储 = **SQLite 单文件**（modernc.org/sqlite 纯 Go 无 CGO，WAL 模式，单写者同步管线 + 多读者网关，备份 = 文件拷贝）；**生产查询目标不变 = PostgreSQL 只读从库**（本 ADR 不涉及查询目标扩展）。SQLite 是 **v1 唯一运行时实现**——检索实现只有一套（五条原语 + RRF）；PG 版不再实现，仅作为多机/HA 需求出现时的**升级路径**记录在案。来源：票据 13（issue #14），2026-08-11 拍板。修正 ADR-0002（票据 07）的「独立 PG 实例」存储决策；07 的其余决策（YAML 作者入口、同步管线、五条原语、RRF、OpenAI embedding、不引入图数据库）不变。

## Considered Options

- **向量实现：Go 内存暴力余弦 vs sqlite-vec（SQL 内 KNN）**：暴力余弦（1536 维 × 10⁵ 行 ≈ 几十 ms）零扩展依赖，但向量逻辑游离在 SQL 之外、检索代码两处（SQL + Go 循环）；sqlite-vec 把 KNN 收进 `vec0` 虚拟表（`vec_distance_*`），与 FTS5/普通表同一 SQL 面。**关键事实（2026-03 后）**：modernc.org/sqlite v1.47.0 起内置 sqlite-vec 的 **CGO-free 移植**（`modernc.org/sqlite/vec`，v1.50.0 升到 sqlite-vec v0.1.9）——选 sqlite-vec **不需要** CGO、不需要加载 .so，「纯 Go 零依赖」前提保持。→ **选定 sqlite-vec**（SQL 内 KNN，与「零运维单文件」不冲突）；若未来 sqlite-vec 版本卡住，退路 = Go 暴力余弦（检索接口不变，换实现层）。
- **SQLite 唯一 vs PG 版并行保留**：并行保留需维护两套检索实现（SQL 方言、RRF、测试矩阵都翻倍），而 v1 硬约束是单机部署、没有 PG 版消费者；升级路径的平滑性靠**存储/检索接口抽象**保留，不是靠现在写第二套实现。→ **SQLite 唯一**；PG 仅作多机/HA 升级路径记入本 ADR，不写代码。
- **授权数据落点（下游推论）**：票据 03 决议「授权数据编译进语义存储权限表」——语义存储载体修正后，权限表随载体落到 SQLite（同一同步管线写入、网关加载内存 + 热重载不变）。→ 权限表 = SQLite 表，升级回 PG 时随存储迁移一并走。
- **审计存储（联动票据 04）**：审计日志是否也落 SQLite 属 04 拍板范围，本票只留输入：审计是语义网关进程的**写**侧（相对同步管线是第二写者），SQLite WAL 支持多进程读写但写写互斥、10⁵ 行/日量级下无压力；04 决议时评估「审计落 SQLite（同机单文件）」vs「落 PG 从库（与业务审计同面）」。

## Consequences

- 部署形态：语义层 = 一个 SQLite 单文件 + YAML 作者入口 + Go 同步管线，本地/单机零运维起步；**单机部署是硬约束**，语义层多机/HA 需求出现时回 PG（升级路径：接口抽象不变、换存储实现 + 迁移数据）。
- 检索：FQN 精确 / 指标公式 / 枚举值 = SQLite 原生；边遍历 = WITH RECURSIVE 原生；关键词 = FTS5 前缀 + LIKE 兜底；向量 = sqlite-vec `vec0` 虚拟表 KNN——五条原语语义不变（票据 02 工具面不受影响）。
- 备份 = 文件拷贝（WAL 下先 checkpoint 再拷）；同步管线幂等 upsert / 墓碑 / dry-run 语义不变。
- 修正范围：仅存储载体（ADR-0002 的 PG 实例 → SQLite）；07 其余决策原样生效。票据 08（采集落盘）/ 11（部署拓扑）不硬编码存储载体，无需改票。
- 升级路径（多机/HA 出现时）：存储接口抽象已有 → 实现 SQLite→PG 迁移（数据搬运 + 检索实现切 pgvector）→ 部署拓扑票据 11 已留位。
