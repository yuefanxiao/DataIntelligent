# 审计重构为执行记录：结构化执行日志（非 SQLite 证据存储）

v1 网关的「审计」重构为**执行记录**：每次 MCP 工具调用写一行结构化 JSON 日志（JSONL，宿主机文件 + 轮转）。范围 = **六工具全记** + 认证失败/权限拒绝 + key 生命周期（CLI 侧追加一行）；字段契约 = 时间、用户/key、工具、参数（execute_sql 的 SQL 原文入库、**不脱敏**）、分阶段耗时（认证→权限→解析→执行→返回）、状态（成功/拒绝/超时/解析失败）、行数、truncated、plan_id（透传）、被拒原因。原始数据 ~7 天轮转 + 聚合摘要 ~30 天（喂 08/12）。**不做** SQLite 审计存储、**不做** CLI 审计查询面、**不接** OpenTelemetry。安全证据存储仅在合规政策驱动时按本契约升级。来源：票据 04（issue #5），2026-08-11 拍板。修正 ADR-0005 留给 04 的「审计存储方向」输入——审计不落 SQLite。

## Considered Options

- **安全证据存储（SQLite 单文件 + 保留期 + CLI 查询） vs 执行记录**：审计的传统形态是证据链——事后回答「谁/何时/对哪张表/跑了什么 SQL」。但消费方是信任的本地开发团队 + 表级白名单授权（03），证据链价值配不上运维成本；查询故障（坏查询打垮从库）的处置链 = `statement_timeout` 自愈（03 已定）→ psql `pg_cancel_backend` 手动杀（`pg_stat_activity` 实时可见）→ 执行日志回答「刚才是哪个查询」→ 配置/索引防复发——**全程不需要证据存储**。→ 执行记录；安全证据（SQLite + CLI）仅合规政策驱动时按本契约升级（字段不变，加存储层）。
- **范围：仅 execute_sql vs 六工具全记**：安全视角只关心业务数据面；但执行记录的第三用途（优化数据源）价值大头在语义工具——search_entities 关键词 / get_entity FQN / 边遍历 = 作者入口与授权缺口的直接信号（08 知识采集的输入）。→ 六工具全记 + 认证失败/权限拒绝（安全信号 + 授权缺口信号）+ key 生命周期（CLI 一行，成本≈0）。
- **脱敏：SQL 原文 vs 字面量剥离**：字面量剥离毁排障与昂贵查询分析价值；日志在网关宿主机上，访问边界 = 宿主机权限，与网关同信任域（03「CLI 仅宿主机可运行」同一哲学）。→ 原文入库；合规需求出现时在写入侧做字面量剥离（配置项）。
- **Tracing：per-stage 耗时字段 vs OpenTelemetry**：OTel collector/dashboard 是多机 HA 场景的形态（11 的领地）；v1 单机，分阶段耗时字段 ≈ 80% 价值、5% 成本。→ per-stage 字段；OTel 归 11 升级路径。
- **保留期：原始短保留 + 聚合摘要 vs 统一长保留**：排障/tracing 消费近期原始数据；优化消费（08/12）是聚合分布（哪些查询被拒、哪些超时、哪些走原料路径）。→ 原始 ~7 天轮转 + 聚合摘要 ~30 天；具体数值归 12。

## Consequences

- 字段契约是 08（知识采集：被拒/原料路径/搜索关键词信号）、10（超时/截断/昂贵查询分布）、12（验收指标、保留期/护栏数值）的输入；本票解封 12。
- 执行记录是网关中间件行为（认证→权限→执行各阶段打点），不表现为 MCP 工具——工具面（02）与权限面（03）不变。
- 执行记录**不落 SQLite 语义存储**——不是第三写者，避免写写互斥与保留期清理耦合语义文件（ADR-0005 的 10⁵ 行/日评估不再适用；JSONL 文件 + 轮转无此约束）。
- 故障响应不依赖任何审计设施：自动护栏（statement_timeout/网关超时）+ psql 手动杀 + 日志事后查。
- 合规/安全政策若要求「生产数据访问可追溯」，按本契约字段升级为 SQLite 证据存储 + CLI 查询面，执行记录语义不变。
